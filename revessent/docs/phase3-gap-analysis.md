# Phase 3 — Gap Analysis (written before implementation, per brief §3)

Status legend: **GAP** = missing backend capability · **PARTIAL** = exists but needs server truth · **OK** = already satisfied.

| # | Phase 1 requirement | Phase 2 state today | Phase 3 need | Plan |
|---|---|---|---|---|
| 1 | PostgreSQL 16 + Drizzle + drizzle-kit, migrations in `packages/db` (§3, §5.2) | `packages/db` is an empty stub; no persistence anywhere | **GAP** | Full Drizzle schema from §5.2 DDL, drizzle-kit SQL migrations, RLS policy migration, client, tx + tenant helpers, dev seed |
| 2 | Org model: organizations / memberships / invitations, roles owner/admin/operator/viewer (§5.2, §7.3) | Demo session cookie carries memberships as plain JSON; nothing persistent | **GAP** | §5.2 tables verbatim; role matrix enforced server-side |
| 3 | AuthN: Better Auth, `rv_session` HttpOnly/Secure/Lax, 30-day sliding, argon2id, email-verification contract (§3, §7.1) | Demo session = base64 cookie, no passwords, no users table | **GAP** | Better Auth 1.7.2 identity core (user/session/account/verification tables via Drizzle adapter) behind thin `/api/v1/auth/*` handlers; argon2id via @noble/hashes (params from env; spec params in prod); email verification + password reset as contracts (202 + token records; **no email sending — Phase 4**) |
| 4 | Orgs plugin | Not present | **GAP (scoped)** | **Documented reading:** Better Auth is used for identity+sessions only; org/membership/RBAC tables stay ours (§5.2 DDL explicitly owns `organizations`/`memberships`/`invitations` — using the orgs plugin would create a second source of truth for the same rows) |
| 5 | RBAC matrix server-side (§7.3) | Client-side `can()` only; mock ignores roles for writes | **GAP** | `requireOrgRole()` + per-service action checks; hidden UI stays supplementary |
| 6 | Tenant isolation: query-layer scoping + RLS `app.org_id` + authz middleware (§7.4) | Mock store keyed by slug; no isolation guarantees | **GAP** | Every repo fn takes orgId; `withOrgTx()` does `set local app.org_id`; RLS policies on all org-owned tables incl. join-based for attempt/checkout tables; app role is non-owner so RLS binds |
| 7 | REST `/api/v1` via Next Route Handlers, Zod in/out, problem+json, cursor lists, Idempotency-Key (§6.1) | Mock client only; ApiError/problem shapes exist in contracts | **GAP** | Thin handlers under `apps/web/src/app/api/v1/**` → `packages/server` services → `packages/db`; §6.2 catalog implemented where Phase 3 scope allows; org path-scoped (`/api/v1/orgs/{slug}/...`) — **documented refinement**: catalog's un-scoped paths underspecify multi-org access; path binding keeps tenant explicit and matches Phase 2 client signatures |
| 8 | Approval FSM server-enforced; edit-from-approved → invalidated (§5.3 #3, §13) | FSM lives in `packages/domain` but only the mock enforced it | **GAP** | Server-side transitions via same domain FSM persisted in `recovery_messages.approval_status` + new `message_approvals` history; invariant: no send without approved/auto-approved (send path itself is Phase 4) |
| 9 | Money integer minor units, distinct recovered/exposure/potential/pending (§14) | Domain Money correct in UI layer | **OK / persisted now** | `*_cents bigint` columns per DDL; overview aggregate keeps nullable = never-synced semantics |
| 10 | Audit logging, append-only, no secrets (§15, §5.2) | None | **GAP** | `audit_logs` writes on every state change (actor/org/action/target/diff/ip/ua); WORM grants; redaction from `@revessent/observability` |
| 11 | Security: origin checks on mutations, secure cookies, secret separation, safe errors (§16, §7.5/7.7) | Demo cookie lax; no origin checks | **GAP** | Origin/`Sec-Fetch-Site` check on all mutating routes; Better Auth secure cookie config; Stripe keys envelope-encrypted (AES-256-GCM, `KEY_ENCRYPTION_KEY` env); problem+json never leaks internals |
| 12 | Recovery public route `/c/[token]` SHA-256-hashed, 14d expiry (§6.2, §7.2) | `/recover/[token]` (Phase 2 deviation) | **GAP + Phase 2 correction** | `/c/[token]` becomes canonical first; `/recover/[token]` 307-redirects; `recovery_checkouts.token_hash` stores hash only |
| 13 | Demo/real boundary explicit; prod cannot use fixtures (§10, §23) | Demo mode defaults ON | **GAP** | Config: demo requires explicit env AND non-production; prod+demo → boot failure; test proves it; DemoBar/mocks unreachable in real mode |
| 14 | Entitlements enforced server-side (§1.4) | Client-side PLANS matrix only | **GAP** | Entitlement checks in services (e.g. expansion requires ≥ revessent plan) |
| 15 | Stripe: connection persisted, keys encrypted, no fake sync (§17, §8.1–8.2) | Demo connect stores nothing; fakes a connected status | **GAP** | `stripe_connections` rows with AES-GCM `key_ciphertext`; status honest (`active`, `last_sync_at` null ⇒ "never synced"); sync/execution = Phase 4 |
| 16 | Rate limits (§6.1/§7.1) | None | **GAP (lite)** | In-process limiter on auth routes (5/15min per ip+email); Redis bucket = Phase 4 with workers |
| 17 | Migrations deterministic; empty-DB → app boots (§21) | n/a | **GAP** | drizzle-kit SQL migrations + `migrate()` in code; test: fresh DB → migrate → seed (dev) → services work |
| 18 | Frontend keeps Phase 2 UI, switches to real API (§22) | Client bound to mock singleton | **PARTIAL** | `packages/contracts` gains a fetch-based `RealApiClient` implementing the SAME `ApiClient` interface; `lib/api.ts` selects by config; mock retained for demo/tests only |
| 19 | `packages/core` naming (§11) | Phase 2 named it `packages/domain` | **Deviation (pre-existing)** | Keep `packages/domain` (renaming would churn the Phase 2 baseline); new `packages/server` = services layer. Recorded as deviation from §11 naming |

**Out of scope (later phases, per brief §17/§18):** Stripe sync/write execution, BullMQ workers, real email, AI generation, webhooks processing, scheduled retries.
